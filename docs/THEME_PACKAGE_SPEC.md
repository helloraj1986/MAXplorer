# MAXplorer theme and icon package specification

**Audience:** developers and designers who want to create MAXplorer themes from
configuration files or build tools.

For the ordinary, visual workflow, see
[Create Your Own MAXplorer Theme — No Coding Required](THEME_CREATOR_GUIDE.md).

---

## 1. Format overview

MAXplorer uses two portable JSON packages with custom extensions:

| Extension | Purpose | Format marker |
| --- | --- | --- |
| `.maxTheme` | A complete colour, style, and layout theme | `maxplorer.theme` |
| `.maxIcons` | An icon pack that can be combined with any theme | `maxplorer.icons` |

The packages are self-contained text files. A future version may wrap the same payload
in an archive; consumers must continue to accept the JSON form documented here.

A file is installable only when its `format`, `formatVersion`, and required fields pass
validation. Version `1` is the current schema.

For a shorter, copyable checklist aimed at AI agents, see
[AGENT_THEME_AUTHORING.md](AGENT_THEME_AUTHORING.md). This specification remains the
authoritative reference.

### Comments and annotations

`.maxTheme` and `.maxIcons` files are strict JSON. Standard JSON has no `//` or `/* */`
comments, and adding them makes the package fail to parse.

Use an ignored `_comments` object at the package root for human and agent notes:

```json
{
  "format": "maxplorer.theme",
  "formatVersion": 1,
  "exportedAt": "2026-10-30T17:20:00.000Z",
  "_comments": {
    "about": "Notes for humans. MAXplorer ignores this object.",
    "specification": "docs/THEME_PACKAGE_SPEC.md",
    "safeEditing": "Edit palette and style values only; no CSS or scripts."
  },
  "theme": { }
}
```

Unknown root fields are ignored. `_comments` is therefore safe for documentation, but it is
not retained after import. Do not put instructions that affect parsing or behaviour inside
`_comments`.

## 2. Theme package

```json
{
  "format": "maxplorer.theme",
  "formatVersion": 1,
  "exportedAt": "2026-10-30T10:15:00.000Z",
  "theme": {
    "id": "evening-ink-8f21ac",
    "packageId": "com.maxplorer.theme.evening-ink-8f21ac",
    "name": "Evening Ink",
    "description": "A quiet dark theme for late-night work.",
    "author": "RKM",
    "version": "1.0.0",
    "base": "windows",
    "appearance": "dark",
    "palette": {
      "accent": "#5b8cff",
      "background": "#080b14",
      "surface": "#0e1320",
      "sidebar": "#0a0e19",
      "selection": "#5b8cff",
      "text": "#e8edff",
      "menu": "#151b2b"
    },
    "style": {
      "corners": "rounded",
      "density": "comfortable",
      "borders": "subtle",
      "elevation": "elevated",
      "iconSize": "default",
      "textSize": "default",
      "sidebar": "plain",
      "toolbar": "subtle"
    },
    "iconPackId": "mono-ink",
    "overrides": {},
    "components": {
      "paneDivider": {
        "width": 2,
        "hitAreaWidth": 14,
        "color": null,
        "hoverColor": null,
        "activeColor": null,
        "gripColor": null,
        "showGrip": true,
        "gripVisibility": "hover",
        "activeIndicator": "accent-border",
        "cornerRadius": 1,
        "headerBackground": null,
        "headerBorderColor": null
      }
    },
    "presetId": "midnight-dark",
    "createdAt": "2026-10-30T10:14:00.000Z",
    "updatedAt": "2026-10-30T10:14:30.000Z"
  }
}
```

### Required fields

| Field | Rules |
| --- | --- |
| `id` | Lowercase letters, digits, and hyphens; 2–80 characters. Generated by the creator. |
| `packageId` | Must begin with `com.maxplorer.theme.`. |
| `name` | 1–60 characters after whitespace cleanup. |
| `version` | Must be `"1.0.0"` in format version 1. |
| `base` | `"windows"` or `"finder"`. |
| `appearance` | `"light"` or `"dark"`. |
| `palette` | Seven valid colours. `#rgb`, `#rrggbb`, and `rgb()` are normalised. |
| `style` | All eight choices below. Unknown values fall back to safe defaults. |
| `components` | Optional. Unknown component keys are ignored; invalid divider values are clamped, not rejected. |

### Component configuration

`components.paneDivider` customises the dual-pane divider and active-pane indicator
without shipping CSS. Every field is optional. Missing colours are derived from the
theme’s border/accent/surface tokens with a guaranteed visible contrast step.

| Key | Allowed values | Default |
| --- | --- | --- |
| `width` | number 1–8 (visible line, logical px) | `2` |
| `hitAreaWidth` | number 12–28 (pointer target); always larger than `width` | `14` |
| `color` | colour or `null` (derive from strong border) | `null` |
| `hoverColor` | colour or `null` (derive from accent/text) | `null` |
| `activeColor` | colour or `null` (derive from accent) | `null` |
| `gripColor` | colour or `null` (derive from muted text) | `null` |
| `showGrip` | boolean | `true` |
| `gripVisibility` | `hover`, `always`, `never` | `hover` |
| `activeIndicator` | `accent-border`, `top-line`, `header`, `none` | `accent-border` |
| `cornerRadius` | number 0–8 | `1` |
| `headerBackground` | colour or `null` (derive from toolbar surface) | `null` |
| `headerBorderColor` | colour or `null` (derive from strong border) | `null` |

A theme may opt out of the grip (`showGrip: false` or `gripVisibility: "never"`) for a flat
minimalist divider. The active indicator is rendered with an inset box-shadow or a header
tint, so switching panes never changes layout dimensions. Invalid values are clamped and
reported as import warnings; the theme still installs. Existing packages without
`components` continue to load unchanged.

Minimal example:

```json
{
  "components": {
    "paneDivider": {
      "width": 2,
      "hitAreaWidth": 16,
      "activeIndicator": "top-line",
      "gripVisibility": "hover"
    }
  }
}
```


### Style values

| Key | Allowed values |
| --- | --- |
| `corners` | `square`, `soft`, `rounded` |
| `density` | `compact`, `comfortable`, `spacious` |
| `borders` | `minimal`, `subtle`, `prominent` |
| `elevation` | `flat`, `elevated` |
| `iconSize` | `small`, `default`, `large` |
| `textSize` | `small`, `default`, `large` |
| `sidebar` | `plain`, `tinted`, `contrast` |
| `toolbar` | `flat`, `subtle`, `elevated` |

`base` is the layout family: the Windows command-bar shell or the Finder source-list
shell. `appearance` is independent from the application’s system/light/dark preference
when the custom theme is active.

`iconPackId` may be `null` to follow the application-wide icon pack.

`presetId` is informational. It powers the “Look” label in the creator. A manually
edited theme may set it to `null`.

### Two persistence keys

| Key | Contents |
| --- | --- |
| `maxplorer-appearance-v1` | Theme library, active theme id, custom icon packs, active pack |
| `maxplorer-theme-draft-v1` | Unfinished design, current step, and Simple/Advanced mode |

Both readers are tolerant: corrupt or older data falls back to an empty library or a
safe default. Themes are limited to 200 entries and imported icon packs to 100.

## 4. How a friendly design becomes application tokens

`themeCssVariables(design)` generates the complete CSS custom property set consumed by
the existing components. It derives:

- surface hierarchy and hover/pressed states;
- readable secondary and muted text using WCAG calculations;
- accent foreground text;
- selection, focus, menu, status bar, scrollbar, and overlay colours;
- radius, shadows, and font scale;
- Finder-specific sidebar and toolbar variables;
- dual-pane divider, grip, active-indicator and pane-header tokens. The divider colour
  fallback is contrast-checked against the active surface so it is never invisible.

`applyThemeDesign(design, iconPack)`:

1. applies the icon pack variables;
2. applies the theme tokens as inline custom properties on `<html>`;
3. sets `data-custom-theme`, `data-ui-theme`, `data-theme`, `data-density`,
   `data-text-size`, `data-icon-size`, `data-theme-corners`, `data-theme-borders`,
   `data-pane-grip`, and `data-pane-indicator`.

`clearThemeDesign()` removes those properties before a built-in theme takes over.
`useTheme()` in `src/hooks/useTheme.ts` keeps this state in sync with the store.

### Advanced token overrides

`theme.overrides` is a string-to-string map. Only these CSS custom properties are
accepted:

```
--accent --accent-fill --accent-text --accent-border --accent-soft --accent-tint
--mica --mica-2 --surface --surface-raised --surface-2 --surface-3 --field
--text --text-2 --text-3 --text-disabled
--border --border-strong --hover --pressed --selected --selected-inactive
--pane-divider-color --pane-divider-hover-color --pane-divider-active-color
--pane-divider-grip-color --pane-active-indicator-color
--pane-header-background --pane-header-border-color --pane-focus-ring-color
--selection-border --menu --menu-border --menu-hover --statusbar
--scrollbar --scrollbar-hover --focus-ring --danger --danger-text --warning --success
--theme-background --theme-sidebar --theme-toolbar --theme-radius
--radius --radius-menu --shadow-1 --shadow-2 --overlay
--font-ui --font-display --icon-stroke
--folder-back-top --folder-back-bottom --folder-front-top --folder-front-bottom
--folder-stroke --folder-shine --storage-led --app-tile-accent
```

Values are sanitized by `sanitizeTokenValue`. Strings containing `;`, `{`, `}`, `<`,
`>`, `@`, `url(...)`, `expression(...)`, `javascript:`, or backslashes are rejected.
Unknown token names are ignored. Imported themes therefore cannot inject CSS, markup,
scripts, or network requests.

## 5. Icon pack package

```json
{
  "format": "maxplorer.icons",
  "formatVersion": 1,
  "exportedAt": "2026-10-30T10:20:00.000Z",
  "iconPack": {
    "id": "my-cool-icons",
    "name": "My Cool Icons",
    "description": "Rounded folders with a mint accent.",
    "author": "RKM",
    "builtIn": false,
    "strokeWidth": 1.7,
    "corner": "rounded",
    "monochrome": false,
    "folder": {
      "backTop": "#a7f3d0",
      "backBottom": "#34d399",
      "frontTop": "#d1fae5",
      "frontBottom": "#6ee7b7",
      "stroke": "#065f46",
      "shine": "#ffffff"
    },
    "accent": "#10b981"
  }
}
```

Icon packs style the existing icon system through tokens:

- `strokeWidth` — chrome icon stroke, clamped to 1.1–2.75.
- `corner` — informational shape choice.
- `monochrome` — maps category accents and transfer accents to graphite.
- `folder` — the four gradient stops plus stroke and shine colours.
- `accent` — optional storage/app accent.

Built-in packs are listed in `src/lib/appearance/iconPacks.ts`. Imported packs are
stored as custom entries and can never replace a built-in pack id.

Icon packs cannot execute code, add SVG markup, or fetch external assets in format
version 1. Richer asset mapping would require a future schema and a new validation path.

## 6. Import and validation pipeline

The UI file input accepts `.maxTheme`, `.maxIcons`, and `application/json`.

```
user selects file
  -> readPackageFile (maximum 1 MB)
  -> parseThemePackage
       format === "maxplorer.theme"
       formatVersion === 1
       normalizeThemeDesign
  -> if that fails, parseIconPackPackage
  -> preview window with validation issues
  -> user clicks Install
  -> appearance store inserts a unique library entry
```

`parseThemePackage` rejects oversized files, invalid JSON, wrong format markers, future
format versions, and themes without a valid name. Colliding ids are assigned a fresh
identity by `importTheme`; an imported package cannot overwrite an existing saved theme.
Invalid `components.paneDivider` values are repaired with safe defaults and returned as
`warnings` on the parse result for theme developers; they never reject an otherwise valid
theme.

Export uses the desktop command `save_appearance_package(fileName, contents)`:

- maximum 1,000,000 bytes;
- the file name must end in `.maxTheme` or `.maxIcons`;
- path separators and unsafe characters are replaced;
- the file is written to `~/Downloads` (or the home folder when Downloads is absent);
- an existing file is never overwritten (`-2`, `-3`, … is appended);
- the absolute path is returned to the UI.

Share copies the package JSON to the clipboard. It does not upload anything.

## 7. AI-assisted creation

`src/lib/appearance/ai.ts` defines:

```ts
export interface ThemeAIProvider {
  id: string;
  label: string;
  available(): boolean;
  generate(request: {
    prompt: string;
    baseDesign?: ThemeDesign;
  }): Promise<{
    design: ThemeDesign;
    summary: string;
    provider: string;
  }>;
}
```

`localThemeProvider` is always available. It maps keywords to supported presets,
appearance, accent hues, style choices, and icon families. It requires no network,
account, or key. Its output is passed through `normalizeThemeDesign` before use, so it
can only produce supported tokens and valid enum values.

To add a provider:

1. Implement `ThemeAIProvider` in a new module.
2. Ensure `available()` reflects explicit user configuration.
3. Return a `ThemeDesign`; never return HTML, CSS, JavaScript, or executable content.
4. Register it in `themeProviders`.
5. Keep `localThemeProvider` as the final fallback.
6. Add tests for unavailable, malformed, and unsupported-token responses.

The UI must always show a preview before applying generated output.

## 8. Adding a new built-in template

1. Add a `ThemePreset` entry to `THEME_PRESETS` in
   `src/lib/appearance/presets.ts`.
2. Use a coordinated palette with readable primary text (WCAG 4.5:1 or better).
3. Choose a base (`windows` / `finder`), appearance, full style object, and a compatible
   built-in icon pack.
4. Add the template to the creator automatically by extending the array; no UI changes
   are needed.
5. Add or update tests in `src/lib/appearance/appearance.test.ts`.

Templates are code-defined and separate from the user library. Selecting one creates a
copy with a new identity; the template itself is never stored or modified.

## 10. Deliberate limitations

- Format version 1 stores JSON directly; there is no binary asset archive.
- Export goes to Downloads rather than opening a native save panel.
- Share copies package text; it does not post to a service.
- Icon packs are token-based and use the existing Lucide/SVG icon system.
- Advanced Mode exposes a curated token list, not arbitrary component-specific CSS.
- AI creation is optional and local. A remote provider is not configured by default.
- The Theme Creator draft is local to the current Mac’s application storage.
- Saving a theme never modifies the built-in Windows 11 or Finder packages.
